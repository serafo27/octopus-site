Every project, its tasks and its Claude Code sessions, in one window.

Octopus is a Mac app for people who build software with Claude Code. Each project gets a task board, its documentation and as many terminals as you need, and you can see which sessions are working, which are idle and which are waiting for you.

Download for Mac

For Apple Silicon and Intel Macs. Needs Claude Code.

From a task to a reviewed change

Octopus is built around one loop: write down what needs doing, hand it to Claude, look at what came back.

  1. Write the task

    Quick add takes priority, tags and project in one line: Fix the login redirect !high #auth @checkout. Link the documents and pages Claude should read with @.

  2. Start Claude

    Octopus opens a Claude Code session in the project's folder with the task, its description and everything it links to as the first request. The task moves to In progress.

  3. Keep an eye on it

    Each session has a dot:  working,  idle,  waiting for you. Work on something else and come back when it rings.

  4. Review and close

    When Claude finishes, the task moves to Review. Read the diff file by file in the Git tab, commit, and mark it done.

What's in the window

Tasks live in the repository

Each task is a Markdown file in the project's .octopus/tasks folder, so the whole team shares the board through git. One file per task means no merge conflicts and pull requests you can read. Claude can add tasks or close them by editing a file, and the board updates as files change.

Prefer to keep them private? Move a project's tasks to this Mac only.

.octopus/tasks/fix-login-redirect-7f3a2c.md
---
title: Fix the login redirect
status: doing      # todo | doing | review | done
priority: high
run: npm test -- auth
---
After sign-in, users land on / instead of
the page they came from. See
[Auth design](octopus://doc/docs/auth.md).

Terminals that know what they're doing

Claude sessions and shells run in the project's folder, side by side or in a window of their own. Octopus remembers them and resumes the conversation after a restart.

Sessions from other apps too

Claude Code running in Terminal, iTerm2, VS Code, Cursor, Warp or Ghostty shows up under its project, with the conversation's title and whether it's working.

Documentation next to the work

Read and edit a project's Markdown docs in a tab. With Mido installed you get its full editor: Mermaid, KaTeX, comments, search.

Notebooks and databases

Pages for specs and notes, with to-dos that are real tasks. Databases with table, board, list and calendar views, relations, rollups and formulas.

Git and review

Changes, staging, commits, branches and a graph. The review tab shows every changed file on one page and remembers which ones you've already read.

Links between everything

Tasks, pages and documents link to each other with plain Markdown links that read fine on GitHub. Every item lists what links to it.

Run a task's check

Give a task a command, like npm test. Run it from the card: success moves the task to Review, a failure tells you the exit code.

More than one Claude account

Use your personal account in one project and your work account in another. Octopus starts every session, and resumes it, in the right one.

Build the section you're missing

An extension adds a section of its own to Octopus: a dashboard for your logs, a client for an internal API, a release checklist. You don't need to know the SDK. Describe what you want and Claude writes it inside Octopus, while you watch it reload with every change.

  1. Describe it

    New extension asks what it should do and opens a Claude Code session in its folder, next to the live page.

  2. Allow what it asks for

    An extension only reaches what its manifest declares: specific hosts, Claude, tasks, documentation. You approve it before it runs, and again if it asks for more.

  3. Share it

    Publish pushes it to a marketplace, any git repository, as a branch ready for a pull request. Teammates install it and get updates from there.

~/.octopus/extensions/log-explorer/manifest.json
{
  "name": "Log explorer",
  "description": "Search checkout logs, file tasks",
  "icon": "pulse",
  "version": "1.2.0",
  "permissions": {
    "http": ["https://logs.internal/api/"],
    "claude": true,
    "tasks": true
  }
}
// index.html + plain files, no build step
await octopus.ready();
const res = await octopus.http.fetch(url);
const why = await octopus.claude.ask(
  "Group these errors by cause: " + res.text());
await octopus.tasks.create({ title, body: why });

Extensions are plain HTML, CSS and JavaScript in a sandbox with its own origin. They use Octopus's theme automatically and talk to the app only through its SDK: HTTP to the hosts you allowed, Claude (read-only), tasks, projects, documentation, storage.

Builds that aren't notarized by Apple yet are stopped by Gatekeeper the first time. Open System Settings › Privacy & Security and choose Open Anyway next to Octopus, or run:

xattr -dr com.apple.quarantine /Applications/Octopus.app
