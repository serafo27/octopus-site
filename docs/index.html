Tasks

A board for every project, kept in its repository.

Each task is a small Markdown file in .octopus/tasks, so your team shares the board through git and Claude can read and update it.

  • Quick add: Fix the redirect !high #auth
  • One file per task: no merge conflicts
  • Checklists, tags, priorities, filters

Claude on a task

Start Claude on a task. It already knows the context.

Claude Code opens in the project's folder with the task, its checklist and every document and page it links to. When Claude finishes, the task moves to Review.

  • Links to docs, pages and other tasks travel with it
  • A command per task, like npm test, to check it's done
  • Its sessions and runs, listed on the task

Sessions

Know which session is working and which needs you.

Every Claude Code session and shell, across projects, in one place. Each has a state, so you can work on something else until one asks for you.

  • Working
  • Waiting for you
  • Idle

It also finds Claude Code running in Terminal, iTerm2, VS Code, Cursor, Warp and Ghostty, under the right project.

Documentation

The project's docs, one tab away from the work.

Read and edit the Markdown in your repository, or ask Claude to update it. With Mido installed you get its full editor, with diagrams, math and comments.

  • Read, split and edit modes
  • Renaming a document updates the links to it

Git and review

Review what Claude changed before you commit it.

Changes, staging, branches and history, with side-by-side diffs. The review page shows every changed file at once and remembers what you've read.

  • Commit, push, pull, merge, resolve conflicts
  • A graph of the branch's history

Notebooks

Specs and notes, with tasks that are real tasks.

Pages for everything that isn't code. A to-do on a page is a task on the board, and databases track the rest with table, board, list and calendar views.

  • Slash commands, code blocks, callouts, links
  • Relations, rollups and formulas in databases

Priorities

What matters next, across every project.

Open tasks from all your projects in one list, by priority, with the sessions that are running above them. General tasks without a project live here too.

Extensions

Missing something? Describe it, and Claude builds it inside Octopus.

An extension adds a section of its own: a log viewer, a client for an internal API, a standup summary. It's plain HTML and JavaScript, written by Claude while you watch it reload.

  1. Create with Claude

    Say what it should do. Claude writes it in a session next to the live page.

  2. Allow what it reaches

    It only gets the hosts, Claude access, tasks or docs its manifest declares, once you approve them.

  3. Share with your team

    Publish to a marketplace, any git repository. Teammates install it and get updates.

// index.html of an extension: no build step
const res = await octopus.http.fetch("https://logs.internal/api/errors");
const summary = await octopus.claude.ask("Group these errors by cause: " + res.text());
await octopus.tasks.create({ title: "Fix the top error", body: summary });

macOS says Octopus can't be opened

Until builds are notarized by Apple, macOS asks the first time. Open System Settings › Privacy & Security and choose Open Anyway, or run:

xattr -dr com.apple.quarantine /Applications/Octopus.app
